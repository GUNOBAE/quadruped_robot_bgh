# BGH DayLab — 최대 12시간 로컬 비교 실험

## 1. 먼저 바로잡은 오류

RUN_VISIBLE_SWING_V2.cmd의 if 괄호 블록 안에 있던 안내문 `(fixed-base bench helper).`가 Windows CMD 파서와 충돌했다. 재부팅, CAD, MuJoCo 설치의 문제가 아니다. 해당 런처를 블록 없는 형태로 수정했다. 아래 학습 묶음은 CMD 파일 대신 Python을 직접 실행한다.

## 2. 오늘 수행하는 것 / 하지 않는 것

이것은 실제 로봇 제어가 아니라, 기존 Physics V1 또는 physics_rl_v0.xml의 **자유 몸체 + 중력 + 지면 접촉**에서 실행하는 실험이다. 고정 몸체 미리보기나 qpos 애니메이션이 아니다.

원래 질량·관성·구동축·토크 한계·각도 범위를 유지한다. 토크를 몰래 키우거나 무게를 줄이지 않는다. 하지만 기존 값 자체가 아직 실물에서 교정되지 않은 임시값이라는 한계는 남는다.

훈련 중 CAD 시각 메쉬만 생략한다. 원본 모델에 명시된 관성과 충돌 형상은 그대로 사용한다. 결과 재생에서는 원래 CAD 메쉬를 다시 읽는다. 원본 Fusion, output의 기존 XML, 과거 PPO 정책과 로그는 수정하지 않는다.

**전체 방향 보행을 보장하는 패키지가 아니다.** 이번 학습/평가는 전진·후진·정지에 한정한다. 목표 직선 속도는 ±0.04m/s로 낮추고, 같은 목표를 모든 후보에 적용한다. 옆걸음·회전을 이번에 배웠다고 평가하지 않는다.

## 3. 비교하는 네 설정

| 이름 | 변경 | 질문 |
|---|---|---|
| A_reference | 기존과 유사한 보상, 초기 탐색 표준편차 1, 엔트로피 계수 0.005 | 동일한 새 관찰값/초기자세에서 기준 성능은? |
| B_low_noise | A에서 탐색 표준편차를 0.15~0.5로 제한, 엔트로피 계수 0 | 탐색 폭을 제한하면 출력 포화가 줄어드는가? |
| C_posture | B에서 몸체 높이·기울기 벌점, 정지 기준을 뺀 속도 보상 등으로 변경 | 웅크리기보다 지속 이동이 유리해지는가? |
| D_gait_residual | C에서 3차원 발 궤적의 수치 IK 기준 명령 + 최대 ±0.06rad 잔차 | 동작의 초안을 주면 더 잘 배우는가? |

A도 과거 환경의 완전한 복제는 아니다. 네 설정 모두 새 59차원 관찰, 같은 초기 안정 자세, 같은 목표속도와 평가 기준을 사용한다. 과거 정책 파일은 이 환경과 호환되지 않아 불러오지 않는다.

D의 기준 궤적은 **검증된 Crawl 보행이 아니다.** 수치 Jacobian으로 만든 실험적 주기 목표다. 처음 중력 아래 세 조합의 보폭/발높이/주기를 시험하고 가장 나은 조합을 사용한다. 실패하면 실패로 기록한다.

## 4. 자동 실행 순서

1. 기존 물리 XML을 새 날짜별 실험 폴더에 복사하고 SHA-256 및 패키지 버전을 기록한다.
2. 중력·접촉 ON, 12개 구동축, 16개 폐루프 접합 제약을 검사한다.
3. 목표각 0으로 기본 서기가 유지되는지 검사한다. 이 조건부터 실패하면 긴 학습을 시작하지 않는다.
4. 네 다리의 수치 Jacobian을 계산하고, 자유 몸체에서 세 가지 기본 발 궤적을 시험한다.
5. 네 설정 × 초기 난수 seed 11/29 = 8개 독립 후보를 순차적으로 새로 학습한다.
6. 약 25,088 제어 결정마다 별도 환경에서 6초 시험을 한다. 최근 상태와 최고 상태를 따로 저장한다.
7. 초기 후보는 각각 최대 40분. 나머지 시간 중 유망한 두 후보만 각각 최대 3시간 이어서 학습한다.
8. 각 후보는 모델 선택에 사용하지 않은 seed와 마찰/접촉 유연성 변화로 별도 평가한다.
9. SUMMARY.md, ranking.csv, JSON 기록, results_bundle.zip을 생성한다.

전부 같은 설정으로 12시간을 꽉 채우는 방식이 아니다. 수치 오류, 기본 서기 실패, 반복적 무개선, 유망한 후보 없음이면 일찍 종료한다. 전체 시간 예산에는 사전 검사와 저장 시간이 포함되며, 종료 전 여유 시간을 남긴다. 외부 OS 멈춤/전원 차단은 프로그램이 복구를 보장하지 않는다.

## 5. 왜 평균 보상 대신 마지막 구간을 평가하나?

처음 주저앉으며 5cm 밀린 뒤 멈춰도 누적 이동량은 5cm다. 이것을 보행으로 착각하지 않도록 **6초 실험 중 마지막 2초의 평균 속도**를 사용한다.

추가로 목표속도의 50~150% 범위인지, 다른 방향으로 크게 새지 않는지, 몸체가 무명령 기준보다 15mm 이상 낮아지지 않는지, 최대 기울기가 20도 미만인지, 실제로 발이 8mm 이상 들리는 사건이 반복되는지 등을 본다.

이 기준은 실험용 후보 판정이지, 안정적 보행이나 실물 사용의 인증이 아니다. 발 궤적·접촉 순서와 영상을 함께 확인해야 한다.

## 6. Windows 실행

기존 mujoco_cad_preview 폴더에 daylab.py와 daylab_env.py를 추가한다. 기존 가상환경을 재사용하며 패키지를 자동 업그레이드하지 않는다.

    .\.venv\Scripts\python.exe daylab.py --hours 12

학습창을 닫지 않는다. 프로그램은 Windows의 자동 절전을 실행 중 일시적으로 억제하고 종료 시 해제한다. 화면만 꺼져도 된다. 사용자가 직접 절전/종료하거나 노트북 덮개를 닫는 행위까지 막지는 않는다. 전원과 통풍을 확보한다.

처음 출력에서 `PREFLIGHT PASSED` 및 `START TRIAL`을 확인한다. 이후 창에 MuJoCo 화면이 없는 것은 정상이다. 자식 학습 로그는 각 실험 폴더의 console.log에 기록한다.

실행 시작 실패 시에는 마지막 오류를 읽는다. 이미 학습을 시작했다면 Ctrl+C로 중단할 수 있지만, 강제 중단 시 현재 자식의 미저장 구간은 잃을 수 있다. 주기적으로 저장된 best.zip/last.zip은 보존한다.

## 7. 저녁에 볼 결과

실험 경로는 output/daylab/LATEST.txt에 저장된다.

    $run = Get-Content .\output\daylab\LATEST.txt
    Invoke-Item $run

최상위 파일:
- SUMMARY.md: 종료 이유와 후보 순위
- ranking.csv / ranking.json: 모든 후보의 정량 비교
- preflight.json: 무명령 서기와 학습 없는 기준 궤적의 결과
- results_bundle.zip: 분석용 JSON/CSV/로그 묶음, 정책 ZIP과 CAD는 제외

각 후보 폴더:
- best.zip: 평가 점수가 가장 나았던 정책
- last.zip: 마지막으로 저장한 정책
- config.json: 설정·seed·원본 hash
- best_evaluation.json: 선택에 사용한 평가
- holdout.json: 별도 seed/접촉 조건의 평가
- history.json: 성능 변화
- console.log: 실행 기록

최상위 후보를 원래 CAD 외형으로 재생:

    .\.venv\Scripts\python.exe daylab.py --view-best --direction forward

후진은 `--direction backward`로 바꾼다. 제일 높은 점수라도 못 걸을 수 있다. 화면은 창을 닫을 때까지 반복한다.

## 8. 검증 범위

자동 검사는 같은 관절 참조에서 재생성한 간략 물리 모델의 짧은 실행이다. 사용자 CAD의 실제 12시간 학습 결과나 실제 로봇 보행을 보증하지 않는다. 학습 결과는 로컬 PC에서 생성된다. ChatGPT가 사용자의 PC를 원격으로 가동하거나 백그라운드에서 학습을 감시하는 방식이 아니다.
