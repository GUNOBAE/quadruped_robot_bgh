# Flow Lab V1 — 몸체/발 움직임 겹치기와 완료 알림

## 목적

기존 제어기는 몸체 shift -> 발 상승 -> 수평 이동 -> 하강 -> 착지 대기의 구간들을 따로 실행했다. 시간을 줄이는 탐색만으로는 이 구조가 바뀌지 않았다.

새 실험은 지지 자세들을 미리 계산하고, 몸체 목표를 구간마다 정지시키지 않고 연결한다. 발도 위로 올라가면서 동시에 앞/뒤/대각선으로 이동한다. 이는 새 PPO 신경망 학습이 아니라 **제어 구조 변경 + 병렬 파라미터 탐색**이다.

원본 질량/관성/토크/각도 제한/마찰/중력/지면 접촉을 유지한다. 몸체에 외력을 주거나 실제 시뮬레이션 qpos를 강제로 이동시키지 않는다. 기존 LinkageRig와 OmniCrawl의 폐루프 IK·하중 보상·실제 접촉 계산을 재사용한다.

몸체 참조 경로는 위치/속도/가속도를 연결한 5차 Hermite 곡선이다. 실제 몸체의 가속도가 항상 작거나 동작 전체가 완전히 부드럽다는 뜻은 아니다. 발 높이는 연속적인 아치로 만들며 접촉 순간의 실제 응답은 별도로 검사한다.

## 로컬 시험에서 확인한 것과 남은 문제

사용자가 올린 results_bundle(2).zip의 source.xml을 사용했다. MuJoCo 3.17.0 / Linux Python 3.13.5. 표시용 비충돌 메쉬만 생략했다.

같은 12주기 전진 시험에서 이전 기준 설정과 수정 시제품 비교:

| 지표 | 기존 전진 기준 | 시제품 |
|---|---:|---:|
| 평균 전진속도 | 1.263 mm/s | 3.530 mm/s |
| 총 전진 | 191.61 mm | 240.73 mm |
| 측정 시간 | 151.72 s | 68.20 s |
| 거의 정지한 시간 비율 | 25.87% | 6.90% |
| 순간 역행 시간 비율 | 34.98% | 19.59% |
| 최장 정지 구간 | 0.74 s | 0.18 s |
| 좌우 위치 왕복 폭 | 58.75 mm | 58.88 mm |
| 가속도 RMS | 0.205 m/s^2 | 0.347 m/s^2 |

속도는 약 2.79배, 정지 구간은 줄었다. 하지만 좌우 움직임은 여전히 약 6cm이며 가속도 RMS는 약 70% 증가했다. **덜 끊기는 것과 모든 면에서 부드러워지는 것은 다르다.** 이 시제품을 완성된 효율 보행이라고 부르지 않는다. 후진 12주기 물리시험도 수행했지만 순간 역행 비율이 새 기준에 미달해 자동 개선으로 채택할 수 없다.

위 시제품은 stride20mm, lift15mm, slot1.4s, swing_fraction0.6, drift0.4, forward_bias0.03이었다. 여러 항목을 함께 바꾼 결과이며 각 항목의 독립적 인과 기여도를 검증한 것은 아니다. 전진 후보는 마찰 0.9/1.1배에서 각각 6주기 추가 시험도 수행했다. 사용자 Windows와 모든 방향의 장기 실행을 대신하는 결과가 아니다.

## 측정 기준

100ms 구간의 실제 몸체 이동으로 속도를 계산한다.
- |목표 방향 속도| < 1mm/s: 거의 정지한 시간
- 목표 방향 속도 < -1mm/s: 역행 시간
- 목표 방향 속도 > +1mm/s: 계속 전진하는 시간

이 값은 명령 속도가 아니라 실제 물리 결과다. 초기 준비 이동은 제외하고 마지막 정지 동작은 측정에 포함한다. 발 들기 8mm 이상, 해당 발 수직 접촉력 1N 미만, 나머지 세 발 지지력 각각 2N 초과, 0.2초 이상의 공중 구간, 착지 오차 8mm 미만이라는 기존 게이트를 유지한다.

개선 후보는 같은 방향/주기/마찰의 기준 대비 1.5배 이상 속도, 최소 65% 전진시간, 12% 이하 정지시간, 25% 이하 역행시간 등의 조건을 동시에 만족해야 한다. 기계적 일/거리, 기울기, 좌우 움직임과 가속도도 제한한다. 가속도 기준은 속도가 다른 시험임을 고려한 잠정 실험 기준이며, 실물 안전 한계가 아니다. 원시 가속도 수치와 비율을 숨기지 않고 저장한다.

최종 확인은 12주기와 최소 120mm의 실제 이동, 그리고 마찰 +/-10%에서 각각 6주기다. 애니메이션 배속이나 처음 주저앉을 때 밀린 거리로 개선을 판정하지 않는다.

## 실행 방법

기존 mujoco_cad_preview 폴더에 새 파일 네 개만 추가한다:
- flow_trial.py
- flow_lab.py
- flow_notify.py
- FLOW_LAB_KR.md

기존 linkage_core.py, omni_trial.py, omni_parallel.py와 .venv는 그대로 사용한다. 이전 최적화/뷰어는 먼저 종료한다. 새 코드도 기존 최적화의 lock을 확인한다. 기존 결과·모델·PPO는 덮어쓰지 않는다.

먼저 Windows 소리/팝업 테스트:

```powershell
.\.venv\Scripts\python.exe flow_lab.py --test-alert
```

확인 버튼을 누른 후 시작:

```powershell
.\.venv\Scripts\python.exe flow_lab.py --start --hours 12 --workers 0 --trials 240
```

기본 집중 방향은 전진/후진/오른쪽 앞 대각선이다. 이전 실험과 동일 소스 SHA일 때, 해당 실행에서 선택된 방향별 설정을 기준으로 가져온다. 그 기준도 다시 물리시험한다. 소스가 달라졌으면 보수적인 원래 설정을 새로 검증하며 과거 숫자를 그대로 비교하지 않는다.

모든 평면 이동 방향을 비교하려면:

```powershell
.\.venv\Scripts\python.exe flow_lab.py --start --hours 24 --workers 0 --trials 480 --commands forward,backward,left,right,forward_left,forward_right,backward_left,backward_right
```

회전과 이동 중 방향 전환은 이번 연속 경로 버전의 범위가 아니다. 이전 omni 프로그램의 검증 결과는 유지된다. 각 방향에서 작동하는 연속 경로를 확인하기 전에 연결 명령 전체가 개선됐다고 주장하지 않는다.

## 완료 알림

`--start`는 콘솔과 분리된 supervisor/master/worker를 실행하고 모든 계산 출력을 파일에 기록한다. PowerShell의 선택/QuickEdit 때문에 계산 출력이 막히는 경로를 피한다.

종료 후 결과와 completion.json을 저장하고 계산 worker를 정리한 다음, supervisor가 **현재 Windows 사용자 세션에서 3음 알림과 팝업**을 요청한다. 팝업을 닫아야 다음 계산으로 넘어가는 구조가 아니다. 그 시점의 계산은 이미 끝났다.

성공, 개선 없음, 오류, 사용자가 중지한 상태를 구분한다. 개선하지 못했는데 성공 알림을 내지 않는다. 상태와 결과 폴더 경로를 팝업에 표시한다.

- 음소거/출력 장치 설정이면 소리가 들리지 않을 수 있다.
- PC가 꺼지거나 로그아웃/절전되면 계산과 알림을 보장하지 않는다.
- 이것은 PC 로컬 알림이며 ChatGPT/휴대폰 푸시가 아니다.
- Windows 알림 경로는 CI에서 모의 API로 검사하며 실제 사용자 스피커/바탕화면 표시 여부는 --test-alert로 확인한다.
- 알림을 원하지 않을 때만 --no-alert를 사용한다.
- 재부팅 후 자동 재개는 지원하지 않는다.

## 진행/중지/재생

```powershell
.\.venv\Scripts\python.exe flow_lab.py --status
.\.venv\Scripts\python.exe flow_lab.py --stop
.\.venv\Scripts\python.exe flow_lab.py --view forward
```

이번에는 완료 알림이 있으므로 매번 status를 확인할 필요는 없다. 첫 실행이 RUNNING인지 한 번 확인하는 것은 권장한다.

재생은 새 물리시험이 아니라 **검증한 실제 물리 계산의 1배속 기록**이다. 카메라는 이동을 숨기도록 몸체를 따라가지 않고 전체 이동이 보이도록 고정한다. 개선 판정을 통과한 해당 방향이 없으면 이전 결과를 신형 성공 결과처럼 보여주지 않는다.

결과 폴더:

```powershell
$run = Get-Content .\output\flow_lab\LATEST.txt
Invoke-Item $run
```

SUMMARY.md, selection.json, search.json, completion.json, notification.json, 방향별 report.json과 telemetry.npz/trajectory.npz가 남는다. results_bundle.zip은 분석용 기록/소스/코드만 포함하며 전체 재생 궤적은 원본 실행 폴더에 남는다. 공유 후에도 실행 폴더는 보존한다.

## 연구 범위와 한계

정적 링크식 crawl의 연속성 개선 실험이지 동적 trot이나 sim-to-real 배포가 아니다. 정확한 시뮬레이터 상태를 사용하고, 실제 센서/서보 전기 채널/극성/영점/실리콘 물성은 아직 보정되지 않았다. 기존 발/몸체 접촉체만 유지하며 전체 링크 자기충돌을 검증하지 않는다. 명령/토크 제한을 임의로 높이지 않는다.

더 빠른 후보가 나오더라도 가속도·접촉 충격·좌우 이동이 나빠질 수 있으므로 모든 원시 지표를 함께 확인해야 한다. 불확실한 후보는 저장하되 자동 배포하지 않는다.
