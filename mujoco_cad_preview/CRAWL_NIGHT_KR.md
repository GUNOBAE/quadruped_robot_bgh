# 검증된 느린 걸음의 밤샘 최적화 — Crawl Night

## 무엇을 하는가

이 작업은 PPO 신경망을 다시 학습하는 것이 아니라, 이미 걷는 PR8 제어기의 **보폭과 동작 시간을 자동 최적화**하는 실험이다. 기존 기구학, 하중 보상, 몸체 자세 제어, 자유 몸체/중력/접촉, 질량/관성, 모터 이득, 명령/토크 한계는 유지한다. 실물 모터 I/O는 없다.

초기 몸체 이동 2초, 마지막 정렬 2초는 그대로 둔다. 바꾸는 항목:

| 항목 | 기존 | 검색 범위 |
|---|---:|---:|
| 한 주기 순이동 목표 | 12 mm | 10~20 mm |
| 발 높이 목표 | 15 mm | 12~18 mm |
| 다음 다리 지지 자세로 이동 | 2.0 s | 0.6~2.0 s |
| 들 발의 하중 이관 | 0.5 s | 0.25~0.5 s |
| 발 상승/이동/하강 시간 배율 | 1.0 | 0.4~1.0 |
| 착지 확인 대기 | 0.7 s | 0.3~0.7 s |

먼저 한 변수씩 변경한 후보를 비교한 뒤, 좋은 후보 주변의 조합과 제한된 전체 범위 표본을 시험한다. 시뮬레이션을 반복해서 매개변수를 개선하는 직접 탐색이며, 새로운 neural policy ZIP을 만들지 않는다.

## 시작

기존 작업 폴더에 `linkage_core.py`, `baseline_crawl.py`, `output/physics_v1.xml`이 필요하다. 새 Python 패키지는 없다. 새 `crawl_night.py`, `crawl_tune_trial.py`를 같은 폴더에 받는다.

```powershell
cd C:\quadruped_robot_bgh-feature-mujoco-cad-preview\mujoco_cad_preview
.\.venv\Scripts\python.exe -u crawl_night.py --hours 8
```

최대 8시간이며, `--hours`는 0.1~12 범위다. 후보 최대 1000개, 초기 비교 뒤 80개 후보 동안 의미 있는 개선이 없으면 검색을 조기 종료하고 검증으로 넘어간다. 종료 시각까지 무조건 CPU를 사용하지는 않는다. 최종 검증용 시간을 별도로 남긴다.

처음에는 원래 제어기를 3주기씩 전진/후진 실행한다. 실패하면 최적화를 시작하지 않는다. 시간 조절이 가능한 복사본도 기본 설정으로 원래 이동량을 재현해야 한다.

다음 메시지가 나오면 자동 검색이 시작된 것이다:

`BASELINE VERIFIED. STARTING TIMING/STRIDE SEARCH.`

화면 렌더링 없이 한 후보씩 순차 실행한다. 상세 내용은 후보별 console.log에 남는다. 기존 CAD·PPO·모델 파일은 변경하지 않고 입력 XML과 코드의 복사본 및 SHA256을 기록한다.

## 좋은 후보를 고르는 기준

실패한 후보의 보상이 높다고 채택하지 않는다.

1. 발을 8mm 이상 들어 접촉력이 1N 미만인 시간이 최소 0.2초 있어야 한다.
2. 발이 공중에 있을 때 나머지 세 발이 각각 2N 이상을 지지해야 한다.
3. 착지 접촉력 및 발 배치 오차 검사를 통과해야 한다.
4. 몸체 기울기, 명령/토크 포화, 루프 제약, 실제 순이동 기준을 유지해야 한다.
5. 전진과 후진 모두 기준보다 최소 10% 빠르고, 거리당 기계적 일 근사치가 5% 넘게 악화되지 않아야 한다.

짧은 1주기 검색 -> 후보 최대 5개를 3주기 검증 -> 마찰을 0.9배/1.1배로 바꾼 별도 평가 -> 6주기 연속 검사. 각 마찰 평가에서는 기준 제어기도 같은 조건으로 다시 실행한다. 마찰 변경은 별도 평가에만 적용하고 원본 XML은 바꾸지 않는다.

개선 기준을 끝까지 통과한 후보가 없으면 **원래 느린 걸음을 그대로 보존**한다. 순위 1등이라는 이유만으로 성공이라고 부르지 않는다.

## 효율 지표의 한계

`sampled_abs_mechanical_work_J`는 50Hz에서 측정한 `sum(abs(torque * joint_velocity))`를 시간에 대해 누적한 근사치다. `mechanical_cot_proxy`는 이를 `로봇 무게(N) * 이동 거리(m)`로 나눈 값이다. 비교 시 동일 주기 수와 같은 접촉 조건을 사용한다.

**배터리 소비량이나 실제 전기 효율이 아니다.** 서보가 가만히 버틸 때 흐르는 전류, 모터/드라이버 손실, 전자부품 전력은 포함되지 않는다. 에너지 지표가 좋다고 실물이 그만큼 오래 동작한다고 해석하지 않는다.

모든 후보는 기존 토크와 명령 한계를 유지한다. 작동 범위 밖의 후보를 살리기 위해 모터를 강하게 만들거나 몸체를 가볍게 하지 않는다.

## 중단/절전/보존

- PowerShell을 닫거나 PC를 수동 절전/종료하면 실행이 중단된다.
- 실행 중 Windows 자동 절전 억제를 요청하고 정리 단계에서 해제한다. 화면 꺼짐은 허용한다.
- 정상 중단: Ctrl+C 또는 출력된 실행 폴더에 이름이 STOP인 파일 만들기.
- 각 후보 완료 시 보고서와 선택 상태를 저장한다. 예외/시간 초과가 있어도 완료한 후보 결과는 남는다.
- 같은 작업을 두 개 동시에 실행하지 못하도록 프로세스 잠금을 사용한다.
- 각 후보의 물리 해석이 멈추면 watchdog이 그 자식 프로세스만 종료한다.
- 중단 후 동일 실행을 자동 재개하는 기능은 없다. 새 실행은 별도 폴더를 만든다.
- 원본 변경이 외부에서 감지되면 비교 결과를 신뢰하지 않고 중단한다.

## 아침에 볼 결과

```powershell
$run = Get-Content .\output\crawl_night\LATEST.txt
Invoke-Item $run
```

- SUMMARY.md: 성공 여부와 최종 선택
- selection.json: 채택한 매개변수 또는 기준 동작으로 복귀했다는 설명
- ranking.csv: 짧은 시험에서 속도/기계적 일 비교
- validation.json: 긴 검사와 마찰 변화 검사 결과
- 각 후보의 forward/backward/report.json: 발 지지, 낙상, 목표 추종 정보
- 각 후보의 trajectory.npz / telemetry.npz: 물리시험 상태 및 접촉/각도/토크 기록
- results_bundle.zip: 설정·소스 XML·코드·JSON 보고서. 큰 재생 배열은 로컬에 보관하며 ZIP에서는 제외

공유할 것은 **이번 crawl_night 폴더 안의 results_bundle.zip**이다. 이전 DayLab ZIP과 구분한다.

최종 기록 재생:

```powershell
.\.venv\Scripts\python.exe crawl_night.py --view-best --direction forward
```

1배속 물리시험 기록 재생이다. 실시간 학습도, 새 물리 계산도 아니다. 개선 검증이 없으면 `BASELINE_ONLY_NO_CONFIRMED_IMPROVEMENT`를 표시하고 기존 기준 동작을 보여준다.

## 실행 검증과 남은 한계

로컬 MuJoCo 3.17.0에서 기존 사용자 업로드 ik_swing_fixed.xml을 자유 몸체/중력/접촉 상태로 복원한 모델로 시험했다. 링크·질량·서보 제한은 유지했다. 이 파일이 사용자의 현재 physics_v1.xml과 동일하다고 가정하지 않으며, PC에서 원래 기준 동작을 다시 통과해야 한다.

한 조합(shift=1.0s, swing_scale=0.7, unload=0.35s, land=0.5s)의 3주기 시험:
- 전진 속도 약 0.564 -> 0.881 mm/s
- 후진 속도 약 0.556 -> 0.870 mm/s
- 전후진 모두 12번의 발 들기·지지·착지 검사 통과
- 거리당 기계적 일 근사치는 각각 약 0.31%, 0.09% 증가 (에너지 절감 결과라고 주장하지 않음)

여전히 매우 느린 Crawl이다. 이 수치는 밤샘 검색의 최종 결과나 실물 효율 개선을 보장하지 않는다. 코드의 Windows/Linux 검사와 실제 CAD 물리시험은 별개의 검증이다.

실물 서보 채널/영점/토크/센서 피드백, 실제 실리콘 접촉과 자기충돌은 여전히 미확정이다. 이번에는 전진·후진만 다루며 옆걸음·회전이나 빠른 Trot을 학습했다고 주장하지 않는다.
