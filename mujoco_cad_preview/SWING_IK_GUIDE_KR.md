# BGH Quadruped — 첫 번째 Single-Leg Swing / Numerical IK 학습

> **이 문서의 목적은 보행 완성보다 '내 로봇의 발끝을 내가 정한 위치로 움직이는 원리'를 배우는 것.**
> 대상: 이미 Fusion STL 37개, Physics V1, MuJoCo 설치를 마친 Windows PC.
> **실물 로봇으로 연결하지 않습니다.** Raspberry Pi, PCA9685, IMU 또는 실제 모터에는 명령하지 않습니다.

## 0. 왜 PPO 학습을 잠시 중단하나?

밤샘 약 1,000만 Step 정책은 전진/후진 모두 이동속도 목표에 미달했고,
다리를 번갈아 들기보다 주저앉는 모습을 보였습니다.
정책 Action 출력의 대부분이 한계 근처에 몰리는 문제도 있었습니다.

**먼저 로봇이 구조적으로 발을 '들어서 앞으로 옮길 수 있는지' 검사해야**
보행이 안 되는 이유가 역기구학/관절/물리/보상 중 어디에 있는지 구분할 수 있습니다.

이번 실험은 다음만 검사합니다:
1. 12개 가상 모터 중 FL/FR/BL/BR 한 다리의 3개 모터 식별
2. 모터를 아주 조금 움직일 때 어떤 발끝이 움직이는지 검사
3. 수치 Jacobian으로 '원하는 발끝 이동량'을 '세 관절 목표각'으로 변환
4. 닫힌 연결봉 제약(8개 폐루프)을 유지하며 실제 MuJoCo 시뮬레이션에서 발끝 위치 추종
5. 별도 JSON/CSV에 목표와 실제 위치 오차 기록

중력 **OFF**, 바닥 접촉 **OFF**, 몸체 **고정**, 가상 서보 ±0.14 rad(약 ±8도) 범위.
실제 서보의 최대 회전각이나 토크를 검증한 값이 아닙니다.

## 1. Windows 실행 — 기존 폴더 그대로 사용

Windows PowerShell에서 입력:

    cd C:\quadruped_robot_bgh-feature-mujoco-cad-preview\mujoco_cad_preview

    $base = "https://raw.githubusercontent.com/GUNOBAE/quadruped_robot_bgh/feature/single-leg-swing-ik-v1/mujoco_cad_preview"
    @("swing_ik_v1.py","RUN_SWING_IK.cmd","probe_actuators.py") | ForEach-Object {
        Invoke-WebRequest "$base/$_" -OutFile $_
    }

    .\RUN_SWING_IK.cmd

실행 메뉴에서 **1 = FL 왼쪽 앞다리**를 먼저 선택합니다.
해당 다리의 발끝을:
- **6mm 들어올리기**
- **5mm 앞쪽(-Y)으로 이동**
- **바닥 높이로 다시 낮추기**

목표는 **초록 구체(green sphere)** 로 표시됩니다.
빨간색 등이 아니라 녹색 목표점과 실제 발끝이 얼마나 잘 일치하는지 확인하세요.

아직 몸체가 움직이는 걸음은 아니므로 화면의 몸체가 고정돼 있어도 정상입니다.
모델을 지면에서 자유롭게 움직이며 걷는 것은 다음 단계입니다.

## 2. 반드시 알아야 할 기초 — FK와 IK

**FK = Forward Kinematics (순기구학)**:
각 모터가 어느 각도로 회전한 상태에서 발끝의 위치가 어디인지 계산합니다.

    (모터 3개 각도 q1, q2, q3) --> (발끝 x,y,z)

**IK = Inverse Kinematics (역기구학)**:
발끝을 목표 위치로 옮기려면 모터 3개 각도가 무엇이어야 하는지 찾습니다.

    (원하는 발끝 x,y,z) --> (모터 목표각 q1,q2,q3)

로봇개에는 힌지가 36개 있지만, 독립적인 제어 입력은 12개입니다.
한 다리당 3개의 시험용 가상 모터가 있으며, 다른 힌지는
연결봉 폐루프 제약으로 따라 움직입니다.
이 때문에 일반적인 3-DOF 직렬 로봇팔의 IK 공식을 그대로 쓰지 않습니다.

### 실제 코드의 수치 Jacobian 방식

한 다리의 3개 가상 서보에 각각 작은 각도 δ=0.07rad를 넣어서 발끝이
앞/뒤/위/아래로 얼마나 이동하는지 MuJoCo에서 측정합니다.

예를 들어 첫 서보를 +δ 움직였을 때 발끝 위치를 p(+δ),
-δ 움직였을 때 p(-δ)라고 하면:

    J[:,0] ≈ (p(+δ) - p(-δ)) / (2δ)

나머지 두 서보에도 반복해 크기 3×3의 Jacobian 행렬 J를 얻습니다.
단위는 m/rad입니다. Jacobian의 각 열은 "한 모터를 1rad만큼 바꾸면
발끝이 어느 방향으로 얼마나 움직이는가"를 근사합니다.

    Δp ≈ J · Δq
    Δq ≈ pinv(J) · Δp

여기서 pinv는 유사역행렬(Pseudoinverse)입니다.
J가 랭크(rank) 3이고 조건수(condition number)가 과도하게 크지 않은지
검사하지 않고 무작정 역행렬을 적용하지 않습니다.

또 코드는 원래 각도 단위가 아닌 **세 모터의 목표각(setpoint)** 반응을
경험적으로 미분한 결과입니다. MuJoCo에서 폐루프를 실제로 계산하므로
직렬 로봇의 Jacobian과 동일하지 않을 수 있습니다.

### 왜 목표각을 조금씩 적용하나?

실제 서보의 명령은 한 순간에 큰 각도로 바꾸면 무리한 동작이 될 수 있습니다.
여기서는 시험용으로 **20ms당 최대 0.025rad**만 목표각이 변하도록 제한합니다.
이 값은 **실제 서보를 측정해서 보정한 제한이 아닙니다.**

## 3. 목표 발끝의 이동 경로(Swing Trajectory)

현재 모델 좌표는 X+가 왼쪽, Y-가 전방, Z+가 위쪽입니다.
시작 발끝 p0로부터 아래 목표를 설정합니다:

    x = x0
    y = y0 - 0.005 * 0.5*(1-cos(pi*s))
    z = z0 + 0.006 * sin(pi*s)
    s = 현재 진행 비율 (0부터 1)

s=0: 원래 위치 / 높이
s=0.5: 중간에 발을 가장 높이 들어올리기
s=1: 5mm 전진 / 원래 높이로 내려놓기

**발끝이 바닥을 실제로 밟는지**는 이번 실험에서 검증하지 않습니다.
중력이 켜진 상태에서 지지하는 단계(Stance Phase)가 별도로 필요합니다.

## 4. 실행 후 결과 읽는 법

생성 파일:

- output/ik_swing_report.json — 핵심 요약
- output/ik_swing_trajectory.csv — 매 20ms 목표 좌표와 실제 좌표
- output/ik_swing_fixed.xml — 고정 몸체 테스트용 XML 복사본

확인할 항목:

| 항목 | 의미 |
|---|---|
| achieved_peak_lift_mm | 실제 발끝이 얼마나 위로 올라갔나 |
| achieved_end_forward_mm | 마지막에 앞쪽으로 얼마나 이동했나 |
| max_position_error_mm | 목표 발끝 위치와 실제 발끝 위치의 최대 차이 |
| max_other_feet_drift_mm | 다른 세 발이 예상치 못하게 이동했는가 |
| max_loop_gap_mm | 닫힌 연결봉의 관절 제약점이 벌어지는가 |
| max_force_fraction_of_provisional_limit | 임시 토크 한계에 얼마나 근접했나 |
| jacobian_condition | 세 모터의 발끝 제어가 수학적으로 얼마나 불안정한가 |
| status | 최초 기구학 후보 여부. 실제 보행 성공 인증 아님 |

성공 판정은 매우 보수적인 **실험용 후보 기준**일 뿐, 정확한 발 패드
접촉·서보 한계·중력 아래 서기를 뜻하지 않습니다.

## 5. 문제가 나타나면

- **한 다리를 선택했는데 다른 다리가 움직인다:** 물리 몸체/서보와 발끝 맵핑 검토.
- **발을 못 든다:** Jacobian 조건수, 가동범위, 제어 방향, 관절 연결을 검토.
- **목표 표시와 발끝이 멀다:** 최대 오차, 서보 추종 및 제어 제한을 검토.
- **화면에서 STL 부품이 땅에 떠 보인다:** 먼저 CAD 메쉬의 상대 배치를
  원래 Fusion 모델과 비교해야 합니다. 외형 표시 이상과 실제 물리
  연결 오류는 별개일 수 있습니다.
- **PyMuJoCo 오류:** 콘솔 전체 에러 텍스트를 전달합니다.
- **MuJoCo 모델이 창에서 움직이지 않는다:** 이 단계는 몸체를 고정한 실험이므로 정상입니다.
- **10,000,000 PPO Step을 다시 돌려야 하나?** 아니요. 이미 학습한 정책은 그대로 보존됩니다.

## 6. 다음 단계로 넘어가는 조건

최소한 FL 한 다리에서:
- 목표 높이와 전방 이동이 실제 발끝 움직임으로 발생하고
- 다른 세 발이 의도치 않게 움직이지 않으며
- 연결봉 닫힌 루프가 유지되고
- 가상 토크 출력이 장기간 포화되지 않아야 합니다.

그 뒤 네 다리를 각각 검사하고, 중력과 접촉을 켠 상황에서
**한 다리를 들 때 나머지 세 발로 안정적으로 버티는지** 확인합니다.
이것이 기본적인 저속 Crawl Gait의 기초입니다.

**실물에 사용하려면 별도의 실제 12개 서보 채널/극성/영점/토크
측정 및 실제 실리콘 발 접촉 물성 검증이 반드시 필요합니다.**
